# rig_animation.h

This directory contains the registration interface for a procedural animation system built on the Flecs Entity Component System (ECS) framework. It defines a pipeline of 11 ordered animation systems executing during the PostUpdate phase, covering the full transformation chain from player input through skeletal rigging to final mesh output. Topics include inverse kinematics (IK), procedural foot placement, terrain snapping, head tracking, secondary motion, world-space matrix computation, and JSONL telemetry logging. Suitable for graphics and gameplay engineers familiar with ECS architecture, skeletal animation pipelines, and the Flecs framework.

## Detailed Descriptions

### rig_animation.md rig_animation.md — Procedural Animation System Registration Interface

This API header defines the central registration function `register_rig_systems`, which accepts a Flecs world, an `InputSystem`, a `CameraState`, an `AnimationLogger`, and a player entity as parameters. It wires together a pipeline of 11 ordered systems that execute sequentially during the Flecs `PostUpdate` phase, ensuring correct data dependencies across the full animation chain.

**Pipeline overview (in execution order):**

1. **PlayerMovementSystem** — Processes raw player input to drive locomotion, translating controller or keyboard state into velocity and directional intent.
2. **ActorGroundingSystem** — Snaps the actor to terrain geometry, maintaining correct vertical positioning and surface alignment across uneven ground.
3. **GaitSystem** — Implements procedural foot placement, determining stride timing, step targets, and foot lift based on character velocity and terrain contact.
4. **IKSystem** — Solves two-bone inverse kinematics for both legs and arms, resolving end-effector targets into valid joint rotations within anatomical constraints.
5. **OverlaySystem** — Applies additive animation states on top of the base pose, supporting layered behaviours such as hit reactions, breathing, or weapon handling.
6. **LookAtSystem** — Drives head and neck bone rotations to track a gaze target, blending procedural look-at behaviour with the underlying animation pose.
7. **SkeletonFinaliseSystem** — Computes secondary motion effects such as SmoothDamp-based follow-through, bone cage dynamics, and inertial lag on secondary bones.
8. **RigTransformSystem** — Traverses the skeleton hierarchy to compute final world-space transformation matrices for every bone, ready for skinning or further processing.
9. **MeshGenerationSystem** — Produces procedural geometry output driven by the finalised rig state, enabling dynamic mesh construction tied directly to bone transforms.
10. **AnimationLogSystem** — Emits per-frame animation telemetry in JSONL format via the `AnimationLogger`, supporting debugging, replay, and offline analysis workflows.

**Key design notes:**

- The pipeline is strictly ordered, with each system consuming outputs produced by its predecessors, making execution order critical to correctness.
- The `register_rig_systems` function serves as the single entry point for integrating the entire animation subsystem into a Flecs world, keeping setup logic centralised.
- The use of `CameraState` as a parameter suggests that certain systems (likely `LookAtSystem` or `PlayerMovementSystem`) are camera-aware, enabling view-relative locomotion or gaze direction.
- Telemetry via `AnimationLogSystem` is built into the pipeline rather than bolted on externally, indicating first-class support for animation debugging and data capture.

This file is the primary reference for engineers integrating or extending the procedural animation system, and should be consulted alongside IK solver documentation and Flecs pipeline configuration guides.
