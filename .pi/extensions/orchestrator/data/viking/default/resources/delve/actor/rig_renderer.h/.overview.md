# rig_renderer.h

This directory contains the API reference header for `RigRenderer`, a GPU-accelerated skeletal rig visualization component built on SDL3 GPU and the Flecs ECS framework. It is primarily concerned with debug rendering of skeletal animation rigs in a 3D engine context, covering geometry generation, GPU buffer management, and render pipeline integration. Core topics include vertex buffer management, ECS-driven geometry construction, shared pipeline resources, and a rich set of debug visualization primitives. The target audience is graphics or game engine developers working with skeletal animation, GPU APIs, or ECS-based rendering architectures who need to integrate, extend, or understand rig debug rendering functionality.

## Detailed Descriptions

### rig_renderer.md rig_renderer.md — RigRenderer API Reference

This file is the primary (and sole) reference document for the `RigRenderer` class, providing a comprehensive overview of its design, interface, and internal workings.

**Class Purpose**
`RigRenderer` is responsible for GPU-accelerated debug visualization of skeletal rigs within a 3D rendering system. It integrates with the Flecs ECS framework to query entity/component data at runtime and translates that data into renderable geometry, making it well-suited for animation debugging workflows in game or simulation engines.

**Lifecycle Methods**
The class exposes three core lifecycle methods that map cleanly onto a typical frame loop:

- `init` — Bootstraps the renderer by borrowing a terrain render pipeline and a dummy SSBO (Shader Storage Buffer Object) from an existing `TerrainRenderer` instance. This shared-resource approach avoids redundant GPU state creation and keeps pipeline overhead low.
- `prepare` — Queries the ECS world for relevant rig components, constructs geometry from that data, and uploads the resulting vertices to a GPU vertex buffer via a copy pass. This is where all per-frame geometry building occurs.
- `draw` — Executes the render pass using the shared pipeline, submitting scene uniforms and lighting data alongside the previously uploaded vertex geometry.

**Geometry and Debug Primitives**
A set of private geometry emission methods covers a wide range of debug visualization shapes, all producing `BasaltVertex` output:

- **Cylinders** — Useful for visualizing bone segments or limb extents
- **Bone-shaped octahedra** — Classic skeletal joint representation
- **UV spheres** — General-purpose joint or pivot point markers
- **RGB axis tripods** — Local coordinate frame visualization
- **Solid and wireframe boxes** — Bounding volume or constraint visualization
- **Diamonds** — Compact joint markers
- **Flat circles** — Ground plane projections or range indicators

This breadth of primitives makes `RigRenderer` a flexible tool for diagnosing skeletal animation issues at runtime.

**GPU Buffer Details**
Key technical constraints and design decisions include:

- A **65,536-vertex cap**, corresponding to approximately 2.5 MB of vertex data per frame
- A **persistent mapped staging transfer buffer** for efficient CPU-to-GPU data upload during the prepare phase
- The `rig_vbo` (vertex buffer object) is **owned** by `RigRenderer`, while the pipeline and `dummy_ssbo` are **borrowed references** from `TerrainRenderer`, establishing a clear ownership model

**Integration Notes**
Developers extending or integrating this class should be aware of the dependency on `TerrainRenderer` for pipeline and SSBO resources, the Flecs ECS query model driving geometry construction, and the fixed vertex budget which may require batching or culling strategies for complex rigs. The shared pipeline design implies that `RigRenderer` renders geometry compatible with the terrain shading model, which may influence how lighting and material uniforms are interpreted.
