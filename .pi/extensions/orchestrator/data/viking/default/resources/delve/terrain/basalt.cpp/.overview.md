# basalt.cpp

This directory contains the implementation of procedural basalt column terrain generation for a hexagonal grid-based terrain system. The source file `basalt.cpp` is documented across two reference files covering its core algorithms: plateau detection, BFS-based flood fill, Worley noise-driven column placement, and hex grid mathematics. The code integrates with SDL3, custom hex utilities, and palette/map data structures. It is suitable for intermediate-to-advanced C++ developers working on procedural terrain generation, game engines, or geological simulation tools.

## Detailed Description

### basalt_1.md basalt_1.md — Plateau-Based BFS Column Generation

This file documents the first half of `basalt.cpp`, covering two core functions: `sample_bilinear` and `generate_basalt_columns`.

**`sample_bilinear`** implements boundary-clamped bilinear interpolation across a 2D float heightmap, enabling smooth height lookups at sub-pixel positions. It handles edge cases by clamping coordinates to valid map bounds before interpolating.

**`generate_basalt_columns`** is the primary terrain generation function for the plateau-based approach. It works by:

- **Plateau filtering**: Qualifying terrain regions are selected based on a minimum pixel size threshold (300 pixels) and a maximum aspect ratio of 3.0, ensuring only broad, flat plateaus receive basalt column treatment.
- **BFS flood fill**: Starting from valid plateau seed points, a breadth-first search expands hex columns across connected plateau regions, ensuring contiguous coverage.
- **Per-column height variation**: A `hash2d` function introduces deterministic but varied height offsets per column, giving the terrain a natural, irregular appearance.
- **Terrain map updates**: Pixels within each placed column are marked as `TERRAIN_BASALT` in the map data.

Dependencies include SDL3 for diagnostic logging, custom hex grid utilities, and standard C++ containers. This file is the primary reference for developers implementing or debugging the plateau detection and BFS expansion pipeline.

### basalt_2.md basalt_2.md — Worley Noise-Driven Column Generation and Hex Utilities

This file documents the second half of `basalt.cpp`, introducing an alternative generation algorithm and expanding on hex grid utility usage.

**`generate_basalt_columns_v2`** implements a Worley noise-driven approach that iterates over a hex grid bounded by the full map dimensions, rather than being constrained to pre-detected plateaus. Key features include:

- **Hex grid iteration**: The function systematically walks hex coordinates covering the map area, converting between pixel and hex space using standard hex grid math.
- **Bilinear sampling**: Both height maps and cell value maps are sampled using bilinear interpolation to determine column placement eligibility at each hex position.
- **Liquid mask filtering**: Hex positions overlapping liquid terrain are excluded, ensuring basalt columns only appear on dry land.
- **Density thresholds**: A configurable density parameter controls how frequently columns are placed, allowing sparse or dense basalt field generation.
- **Jitter-based height variation**: Random jitter offsets are applied to column heights, producing more geologically realistic variation than uniform placement.
- **Visible edge computation**: The `compute_visible_edges` helper determines which faces of each hex column are exposed, supporting correct rendering of column geometry.

Both functions populate `HexColumn` structures with height data and register pixels as `TERRAIN_BASALT`. SDL logging is used throughout for diagnostics. This file is the primary reference for developers working with the noise-driven generation path, hex coordinate mathematics, or the rendering pipeline for basalt column geometry.
