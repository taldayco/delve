# basalt.h

This directory contains the C++ API reference for procedural basalt column terrain generation. It defines the core interfaces for creating hexagonal basalt column formations within a simulation or game terrain system, covering two generations of the API: a heightmap-driven approach and a newer Worley noise-parameterized implementation. Key topics include hexagonal grid modeling, heightmaps, plateau data, and noise-based procedural generation. Suitable for C++ game and simulation developers working on procedural terrain systems who are familiar with hexagonal grids and noise-based generation techniques.

## Detailed Descriptions

### basalt.md basalt.md — Basalt Column Generation API Reference

This file serves as the primary API reference for the basalt column generation subsystem. It documents two core functions and one configuration structure, representing a versioned evolution of the procedural terrain generation approach.

**`generate_basalt_columns`** is the original generation function. It accepts a heightmap, grid dimensions, hex size, and plateau data as explicit inputs, producing a vector of `HexColumn` objects as output. It also writes plateau and terrain map data through output parameters. This function is suited for workflows where heightmap and plateau information are already computed and available as direct inputs.

**`generate_basalt_columns_v2`** is the newer implementation, designed around a more data-driven philosophy. Rather than accepting raw heightmap and plateau inputs directly, it uses the `WorleyBasaltParams` struct to encapsulate noise-based configuration, delegating column placement decisions to Worley noise evaluation internally. This reduces the burden on the caller to pre-compute terrain features and instead shifts control toward tunable noise parameters.

**`WorleyBasaltParams`** is the configuration structure introduced alongside `v2`. It exposes three tunable parameters:

- **Density threshold** — controls how densely columns are placed across the terrain surface
- **Jitter scale** — adjusts the randomness and irregularity of column positioning within the hexagonal grid
- **Edge threshold** — governs how column placement responds to detected noise-based edges, shaping the boundaries of basalt formations

Together, these parameters give developers fine-grained control over the visual and structural character of generated basalt fields without requiring manual heightmap manipulation.

**Dependencies** include the terrain hex subsystem (responsible for hexagonal grid management and `HexColumn` data structures) and the contour subsystem (used for plateau and terrain boundary detection). The `MapData` aggregate structure ties these subsystems together as a shared data container passed through the generation pipeline.

**Design evolution:** The progression from `generate_basalt_columns` to `generate_basalt_columns_v2` reflects a deliberate architectural shift — moving away from explicit, caller-managed terrain inputs toward a self-contained, noise-parameterized model. This makes the newer API easier to integrate into procedural pipelines where terrain features are generated on-the-fly rather than pre-baked. Developers maintaining or extending this system should be aware of both versions, as legacy code may depend on the original function signature while newer terrain generation workflows are expected to adopt `v2`.

**Target audience:** C++ developers building or maintaining procedural terrain generation systems, particularly those working with hexagonal grid representations, heightmap pipelines, and noise-based content generation. Familiarity with Worley (cell) noise concepts and hexagonal grid coordinate systems is recommended for effective use of this API.
