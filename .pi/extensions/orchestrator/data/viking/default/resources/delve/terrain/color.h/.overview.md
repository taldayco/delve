All colors are represented as 32-bit ARGB integers. It is best suited for C++ graphics developers who need fast, self-contained color utilities without external library dependencies.

## Detailed Description

### color.md color.h — Pixel-Level Color Utility Functions

This C++ header file defines six inline utility functions for color manipulation, intended for use in graphics rendering and image processing pipelines. All functions operate on 32-bit ARGB integers with a fixed opaque alpha value of `0xFF`, using bitwise operations to extract and recombine individual RGB channels efficiently.

**`lerp_color`**
Performs linear interpolation between two RGB colors using a floating-point parameter `t` in the range `[0.0, 1.0]`. Useful for smooth color transitions, gradients, and animation blending.

**`add_noise_variation`**
Applies position-based pseudo-random noise to a color using a hash function derived from pixel coordinates. This introduces subtle, spatially coherent color variation without requiring external noise libraries — well suited for procedural terrain texturing and surface detail.

**`darken_color`**
Reduces the brightness of a color by a configurable darkness factor, scaling each RGB channel proportionally. Useful for shading, shadow effects, and depth cueing in software renderers.

**`alpha_blend`**
Composites a source color over a destination color using the standard alpha blending formula. Enables transparency effects and layered rendering without requiring a full compositing pipeline.

**`modulate_color`**
Scales all three RGB channels by a single uniform factor. Commonly used for lighting intensity adjustments, tinting, and fog effects in lightweight rendering systems.

**`apply_hex_dither`**
Applies hexagonal-grid-based dithering across an entire pixel buffer. Accepts configurable dither strength and an optional skip color to leave specific pixels unaffected. This function operates at the buffer level rather than per-pixel, making it suitable as a post-processing pass. The hexagonal coordinate system is implemented via a rounding algorithm, producing a visually distinct dither pattern compared to standard square-grid approaches.

**Key Technical Concepts**
- Bitwise RGB channel extraction and packing into 32-bit ARGB integers
- Hash-based pseudo-random noise generation from 2D pixel coordinates
- Hexagonal coordinate rounding for grid-aligned dithering
- Per-pixel and per-buffer manipulation patterns
- Fully inline, header-only implementation with no external dependencies
