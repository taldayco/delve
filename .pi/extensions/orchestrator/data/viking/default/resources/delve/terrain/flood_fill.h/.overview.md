# flood_fill.h

A single-header C++ library implementing a generic, template-based flood fill algorithm for detecting connected regions in 2D grids. Using breadth-first search (BFS), it identifies and returns connected components as collections of flat integer indices. Suitable for intermediate to advanced C++ developers working in image processing, game development, terrain analysis, procedural generation, or any domain requiring grid-based spatial segmentation. Core keywords: flood fill, connected components, BFS, grid traversal, region detection, C++ templates, spatial algorithms.

## Detailed Description

### flood_fill.md flood_fill.md — Algorithm Reference & API Documentation

This document describes the single public function exposed by the header: `flood_fill_regions`. The function signature accepts the following parameters:

- **`width` / `height`** — dimensions of the 2D grid
- **`predicate`** — a template callable (lambda, functor, or function pointer) that determines whether a given cell index should be included in region detection
- **`min_region_size`** *(optional)* — a threshold that filters out connected components smaller than the specified size

Internally, the algorithm maintains a flat boolean array to track visited cells, avoiding redundant processing. For each unvisited cell that satisfies the predicate, a BFS is initiated using a queue. The BFS expands in four cardinal directions (up, down, left, right), collecting all reachable connected cells into a single region represented as a `std::vector<int>` of flat indices. Once BFS completes for a seed cell, the collected region is evaluated against the minimum size threshold; only qualifying regions are appended to the output.

The function returns a `std::vector<std::vector<int>>` — a list of regions, where each region is a list of flat grid indices. Callers can convert flat indices back to 2D coordinates using standard `x = index % width` and `y = index / width` arithmetic.

**Key design decisions highlighted in the documentation:**

- **Flat indexing** simplifies memory layout and avoids nested array overhead, making the implementation cache-friendly and easy to integrate with existing flat data structures (e.g., image buffers, tile maps).
- **Template-based predicate** makes the function highly reusable — the same algorithm can segment terrain types, detect non-zero pixels, identify walkable tiles, or classify any binary or categorical grid property without modification.
- **BFS over DFS** is chosen for its predictable memory usage and avoidance of stack overflow risks on large grids, which would be a concern with recursive DFS implementations.
- **Minimum region size filtering** is a practical convenience for real-world use cases where noise or small isolated cells should be discarded before further processing.
