## Detailed Description

### instanced_terrain.md instanced_terrain.md — API Reference for InstancedTerrain

This file serves as the primary API reference for the `InstancedTerrain` class and its associated data structures. It documents a C++ header designed to enable GPU-accelerated instanced rendering of hexagonal terrain columns using SDL3 and GLM.

**`ColumnInstance` Struct**
The `ColumnInstance` struct is the fundamental per-instance data unit passed to the GPU. It stores a 4x4 model matrix (`glm::mat4`) and an RGBA color value, packed into a fixed **80-byte layout** enforced by a `static_assert`. This strict size guarantee ensures correct alignment and compatibility with GPU buffer expectations, preventing subtle memory layout bugs when data is uploaded to the SSBO.

**`InstancedTerrain` Class**
The `InstancedTerrain` class is the central component of this system, providing a clean interface for the full lifecycle of instanced terrain rendering:

- **Building instance data**: Methods accept `HexColumn` and `TerrainState` inputs to construct CPU-side instance arrays, translating logical hex grid data into per-instance transform matrices and colors.
- **GPU upload**: Handles uploading the CPU-side instance vector to a GPU Shader Storage Buffer Object (SSBO) via `SDL_GPUDevice`, abstracting the low-level buffer creation and data transfer steps.
- **Resource cleanup**: Provides explicit cleanup methods to release GPU resources, following SDL3's resource management patterns.
- **Accessors**: Exposes the SSBO handle, current instance count, and a validity flag so callers can safely query buffer state before issuing draw calls.
- **`cpu_instances` vector**: A publicly accessible `std::vector` of `ColumnInstance` objects, allowing developers to directly inspect or modify instance data on the CPU side before committing it to the GPU.

**Intended Use and Audience**
This header is intended for graphics or game engine developers integrating a hex-grid terrain system into an SDL3-based rendering pipeline. Familiarity with instanced rendering concepts, SSBO binding in shader pipelines, GLM matrix math, and SDL3's GPU abstraction layer is assumed. The design separates CPU data preparation from GPU upload, giving developers flexibility to batch-modify instances before any GPU work occurs.

**Key Technical Details**
- Uses `glm::mat4` for per-instance model transforms
- RGBA color stored alongside the matrix in the 80-byte `ColumnInstance` layout
- SSBO used as the GPU-side buffer type, suitable for large instance arrays
- SDL3 GPU API (`SDL_GPUDevice`) manages buffer lifetime and upload
- Static assertion guards against accidental struct padding or size drift
