# lava.cpp

This directory contains the C++ implementation for procedural lava terrain generation in a tile-based or grid-based game map system. It covers two core systems: triangulated mesh construction from lava pixel data and BFS-based connected-component flood-fill analysis for classifying lava and void terrain regions. Key topics include grid mesh generation, pixel budget management, memory safety, randomized terrain classification, and SDL3 integration. The content is best suited for experienced C++ game developers and engine programmers working with procedural content generation, terrain systems, and performance-conscious memory management.

## Detailed Descriptions

### lava_1.md lava_1.md — Mesh Generation and Flood-Fill Foundation

This file documents the foundational layer of `lava.cpp`, covering two primary functions that together establish the lava terrain pipeline. The first, `generate_lava_grid_mesh`, constructs a triangulated mesh from lava pixel data using a configurable grid spacing approach. It builds a vertex map and assembles triangle indices to produce renderable geometry from raw terrain data. A hard cap of 200×200 cells is enforced during mesh generation to prevent runaway memory allocation in large or malformed maps.

The second function, `generate_lava_and_void`, initiates the connected-component analysis that drives terrain classification. It uses BFS-style flood-fill seeded with `mt19937` for reproducible, randomized results across map generation runs. Pixel budget limits — 50,000 pixels per component and 200,000 pixels total — act as safety valves against excessive memory use during traversal of large contiguous terrain regions.

This file is the entry point for understanding how raw lava pixel data is transformed into both visual mesh geometry and semantically meaningful terrain bodies. It is essential reading for developers integrating or modifying the lava generation pipeline at a structural level.

**Key concepts:** grid mesh generation, vertex map construction, triangle index assembly, flood-fill initialization, `mt19937` seeding, per-component and total pixel budgets, memory safety guards, SDL3.

### lava_2.md lava_2.md — BFS Classification, Filtering, and Map Stamping

This file documents the continuation and completion of the `generate_lava_and_void` function, focusing on the BFS traversal logic and all downstream processing that converts raw connected components into fully classified terrain bodies ready for use by the game engine.

BFS flood-fill traversal is executed with strict pixel budget enforcement at both the per-component and global levels. Components that fall below a minimum threshold of 50 pixels are discarded as noise, while oversized components are capped at `MAX_COMPONENT_PIXELS` to maintain performance. Surviving components are randomly classified as either lava or void terrain regions, introducing variety into the procedurally generated map.

For each accepted component, the code computes a bounding box and aspect ratio, generates a lava grid mesh where applicable, and stamps the terrain body onto the map. A post-stamp pixel-clearing step optimizes memory by releasing pixel data that is no longer needed after stamping. Time offset randomization is applied per body to vary animation phase, preventing visual uniformity across lava surfaces. Basalt terrain is explicitly excluded from lava and void assignment to preserve geological accuracy in the terrain model.

The function returns a structured result containing separate collections of lava body and void body objects, each carrying spatial metadata for use in rendering and gameplay systems.

**Key concepts:** BFS flood-fill, component size filtering, lava/void classification, bounding box computation, aspect ratio, terrain map stamping, pixel budget enforcement, post-stamp memory clearing, animation time offsets, basalt exclusion, SDL logging, procedural content generation.
