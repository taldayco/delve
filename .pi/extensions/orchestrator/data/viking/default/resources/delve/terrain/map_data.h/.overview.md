# map_data.h

This directory contains the core header file for a procedural terrain generation system built on a hex-based map architecture. It defines the foundational `MapData` structure used to organize and manage multiple layers of terrain data, including elevation, liquid simulation, noise inputs, and spatial grid structures. The file is essential for developers building or extending a game engine or simulation framework that relies on procedural world generation. Familiarity with C++, Worley noise, hex grid systems, and fluid simulation concepts is recommended. Key topics include terrain generation, lava bodies, contour lines, elevation mapping, and liquid masking.

## Detailed Description

### map_data.md map_data.h

This C++ header file defines the central `MapData` structure that serves as the backbone of a procedural terrain generation pipeline for a hex-based map system. It is organized into several clearly separated concerns:

**Terrain Type Constants**
Four `int16_t` constants establish the fundamental terrain classifications used throughout the system:
- `TERRAIN_EMPTY` — unassigned or default terrain
- `TERRAIN_BASALT` — solid volcanic rock surface
- `TERRAIN_LAVA` — active or solidified lava terrain
- `TERRAIN_VOID` — absent or null terrain regions

**Raw Noise Inputs**
The struct stores several unprocessed noise and mask layers that feed into the terrain generation pipeline:
- `elevation` — base heightmap data driving terrain shape
- `river_mask` — binary or weighted mask indicating river placement
- `worley` — Worley (cellular) noise values for organic surface variation
- `worley_edge` — edge detection output derived from Worley noise cells
- `worley_cell_value` — per-cell scalar values from the Worley noise computation

**Processed Output Layers**
After noise inputs are transformed through generation algorithms, results are stored in dedicated output fields:
- `final_elevation` — the resolved elevation after all modifications and blending
- `liquid_mask` — indicates which cells contain liquid (lava or water)
- `basalt_height` — height values specific to basalt terrain formations

**Spatial Structures**
The struct also manages higher-level spatial data used for rendering, simulation, and gameplay logic:
- `HexColumn columns` — the primary hex grid column structure organizing cells spatially
- `terrain_map` — a flat or 2D map associating grid positions with terrain type values
- `lava_bodies` — a dynamic collection of connected lava regions, likely used for fluid simulation or rendering grouping
- `void_bodies` — similarly structured collection for void/absent terrain regions
- `contour_lines` — geometric or logical lines representing elevation boundaries, useful for rendering or pathfinding
- `band_map` — a mapping of elevation bands, likely used for biome assignment or visual stratification

**Initialization via `allocate`**
The `allocate` method accepts a width and height parameter and initializes all vector-based data layers to match the grid dimensions. It also resets dynamic collections such as `lava_bodies` and `void_bodies`, ensuring a clean state before terrain generation begins. This method is the expected entry point for setting up a new map instance.

**Intended Audience**
This header is designed for game engine developers, simulation engineers, or technical designers working on procedural world generation systems. It assumes working knowledge of C++ data structures, noise-based terrain algorithms, hex grid coordinate systems, and basic fluid or body-tracking simulation patterns. It serves as a reference and integration point for any subsystem that reads from or writes to the terrain data pipeline.
