## Detailed Description

### noise.md noise.md — Procedural Terrain Heightmap Generation

This C++ source file implements a complete procedural terrain heightmap generation system built around fractal noise synthesis and a series of post-processing passes. The primary entry point is the `generate_heightmap` function, which accepts an output buffer, grid dimensions, a `NoiseParams` configuration struct, and a map scale factor.

**Fractal Noise Generation**
The system uses multi-octave OpenSimplex2 noise via the FastNoiseLite library. Noise is layered across multiple octaves, with each successive octave contributing finer detail at reduced amplitude. The key parameters controlling this behavior are:

- `seed` — initializes the noise function for reproducible or randomized output
- `frequency` — controls the base spatial frequency of the noise
- `octaves` — determines how many noise layers are summed
- `gain` — scales amplitude between successive octaves
- `lacunarity` — scales frequency between successive octaves

**Gradient-Based Erosion Simulation**
After the initial noise pass, a gradient-based erosion step is applied. This process computes local slope magnitudes across the heightmap and reduces amplitude in high-slope regions, softening sharp ridges and producing terrain that more closely resembles naturally eroded landscapes. This step is critical for achieving organic, believable terrain rather than purely mathematical noise patterns.

**Boundary Padding**
To prevent edge artifacts that commonly arise when tiling or sampling near the borders of a generated heightmap, a boundary padding strategy is applied. This ensures that values near the edges of the grid blend smoothly and do not exhibit discontinuities or clamping artifacts.

**Normalization**
The raw output values from the noise and erosion passes are remapped to a clean 0–1 floating-point range. This normalization step ensures consistent downstream usage regardless of the specific parameter configuration used, making the heightmap directly usable as a texture, displacement map, or elevation dataset.

**Discrete Terracing**
The normalized heightmap is then quantized into eight discrete elevation levels, producing a terraced appearance reminiscent of stepped geological formations or stylized game terrain. This pass converts the smooth continuous gradient into a staircase-like structure, which can be used directly or as an intermediate representation for further processing.

**Flood-Fill Region Merging**
The final post-processing step applies a flood-fill region-merging algorithm to the terraced heightmap. Small isolated fragments — terrace regions that fall below a configurable `min_region_size` threshold — are identified and merged into their neighboring regions. This eliminates visual noise in the form of tiny disconnected patches, producing cleaner, more coherent terrace boundaries suitable for rendering or gameplay use.
