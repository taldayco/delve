# noise.h

A C++ header-only API for procedural noise-based terrain generation. This directory contains the interface definition for a heightmap generation system built on fractal Brownian motion (fBm) noise with terracing support. It exposes a clean configuration struct and a single generation function, making it straightforward to integrate into game engines, simulations, or any C++ application requiring procedural terrain. Suitable for C++ game developers and simulation engineers familiar with C++20 features, fractal noise concepts, and heightmap-driven terrain pipelines. Core keywords: procedural generation, heightmap, fractal noise, fBm, terrain, octaves, lacunarity, C++20.

## Detailed Descriptions

### noise.md noise.md — Noise API Reference Header

This file defines the complete public interface for the procedural heightmap generation system. It contains two primary declarations: the `NoiseParams` configuration struct and the `generate_heightmap` function.

**`NoiseParams` Struct**

The `NoiseParams` struct bundles all tunable parameters for the noise generation pipeline into a single, self-documenting configuration object. Its fields and defaults are:

| Parameter | Default | Purpose |
|---|---|---|
| `frequency` | `0.005f` | Controls the spatial scale of the noise; lower values produce broader, smoother features |
| `octaves` | `6` | Number of fractal detail layers stacked together |
| `lacunarity` | `2.0f` | Frequency multiplier between successive octaves |
| `gain` | `0.5f` | Amplitude scaling factor between successive octaves |
| `seed` | `1337` | Integer seed for reproducible noise output |
| `terrace_levels` | `8` | Number of discrete steps applied to create terraced terrain |
| `min_region_size` | `153` | Threshold for region filtering or smoothing passes |

Together, `lacunarity` and `gain` govern the classic fractal Brownian motion (fBm) character of the output: higher lacunarity sharpens fine detail, while lower gain reduces the contribution of higher octaves, producing smoother results.

**`generate_heightmap` Function**

The core generation function has the following signature:

```cpp
void generate_heightmap(
    std::span<float> output,
    int width,
    int height,
    NoiseParams params,
    float map_scale = 1.0f
);
```

- **`output`** — A C++20 `std::span<float>` pointing to a caller-owned buffer that will be filled with normalized heightmap values. The buffer is expected to hold at least `width × height` elements.
- **`width` / `height`** — Dimensions of the terrain grid in samples.
- **`params`** — A `NoiseParams` instance controlling all aspects of noise generation.
- **`map_scale`** — An optional uniform scale multiplier (default `1.0f`) applied to the output, useful for adjusting overall terrain amplitude without modifying the noise parameters directly.

**Key Design Notes**

- The API uses `std::span` (C++20), so callers must compile with at least `/std:c++20` or `-std=c++20`.
- The terracing feature (`terrace_levels`) post-processes the fBm output to produce stepped, plateau-like terrain reminiscent of eroded landscapes or stylized game worlds.
- The `seed` parameter ensures deterministic output, which is critical for reproducible world generation across sessions or distributed systems.
- The interface is intentionally minimal — one struct, one function — making it easy to wrap, mock, or extend in larger terrain pipelines.
