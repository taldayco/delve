# noise_cache.h

This directory contains the `noise_cache.h` C++ header file, which provides a caching layer for procedural noise generation in terrain and world-building systems. It defines the `NoiseCache` structure, enabling developers to store and retrieve previously computed noise results across three terrain-relevant slots — elevation, river, and Worley noise — using FNV-1a parameter hashing for cache validation. Suitable for C++ developers working on procedural generation pipelines who need to eliminate redundant noise computations and improve runtime performance.

## Detailed Descriptions

### noise_cache.md noise_cache.h — NoiseCache Structure API

This C++ header defines the `NoiseCache` structure, a lightweight caching utility designed to prevent redundant computation during procedural noise generation. It is organized around three named cache slots:

- **ELEVATION** — stores noise data used for terrain height generation
- **RIVER** — stores noise data associated with river or flow-based terrain features
- **WORLEY** — stores Worley (cellular) noise data, commonly used for biome or surface detail generation

Each slot can hold up to **three `float` data vectors**, along with a **64-bit parameter hash** used to validate whether the cached result is still applicable to the current generation request.

#### Hashing Strategy

The header includes a `hash_params` template function implementing the **FNV-1a (Fowler–Noll–Vo)** hashing algorithm. This function accepts an arbitrary parameter struct and produces a 64-bit hash representing the full state of the generation parameters. When a `get` request is made, the stored hash is compared against the hash of the incoming parameters — a match signals a cache hit, and the stored vectors are returned without recomputation.

#### Core API

| Method | Description |
|---|---|
| `get(slot, params, out1)` | Retrieve one output vector if cache is valid |
| `get(slot, params, out1, out2)` | Retrieve two output vectors if cache is valid |
| `get(slot, params, out1, out2, out3)` | Retrieve three output vectors if cache is valid |
| `put(slot, params, in1)` | Store one output vector with parameter hash |
| `put(slot, params, in1, in2)` | Store two output vectors with parameter hash |
| `put(slot, params, in1, in2, in3)` | Store three output vectors with parameter hash |
| `invalidate_all()` | Reset all slots, clearing hashes and stored data |

The overloaded `get`/`put` signatures provide flexibility depending on how many output channels a particular noise function produces, keeping the interface ergonomic without requiring callers to manage unused vector slots.

#### Cache Invalidation

The `invalidate_all()` method resets the internal state of every slot, effectively marking all cached data as stale. This is useful when global generation parameters change — such as a new world seed or a terrain configuration update — ensuring no outdated noise data is inadvertently reused.

#### Usage Context

This header is intended for use within **procedural terrain or world generation pipelines** where noise functions (e.g., Perlin, Simplex, Worley) are called repeatedly with identical parameters across different system components. By centralizing cache management in `NoiseCache`, developers avoid duplicating computation across subsystems that independently request the same noise data.

Familiarity with the following is recommended for effective use:
- C++ template programming (for `hash_params`)
- FNV hashing and its trade-offs
- Procedural noise generation concepts (elevation maps, Worley/cellular noise)
- Terrain generation pipeline architecture
