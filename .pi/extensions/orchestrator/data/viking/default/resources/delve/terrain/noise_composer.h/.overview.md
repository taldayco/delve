# noise_composer.h

This directory contains the header file defining the noise composition interface for a procedural terrain generation system in C++. It covers the core API for combining multiple noise layers into cohesive terrain map data, including configuration of elevation thresholds, river parameters, Worley noise, void regions, and terrain terracing. The module serves as the integration layer of the terrain pipeline, bridging individual noise layers with final map output. It is suitable for C++ game developers and simulation engineers familiar with procedural generation techniques and noise-based terrain synthesis.

## Detailed Descriptions

### noise_composer.md noise_composer.md — Noise Composition API Reference

This file is the API reference for `noise_composer.h`, the central header responsible for combining multiple noise layers into final terrain map data. It documents two primary components:

**`CompositionParams` Structure**

This configuration struct controls the high-level characteristics of the generated terrain. Its documented fields and default values are:

| Parameter | Default | Description |
|---|---|---|
| `river_elevation_max` | `0.35` | Elevation threshold below which rivers are placed |
| `void_chance` | `0.3` | Probability of a region being designated as void |
| `terrace_levels` | `8` | Number of discrete terrace steps in the terrain |
| `min_region_size` | `10000` | Minimum allowable size for a terrain region |

These parameters give developers direct control over the visual and structural character of the generated terrain without modifying the underlying noise algorithms.

**`compose_layers` Function**

The core function of this module, `compose_layers`, accepts the following inputs:

- A `MapData` reference — the output target for the composed terrain
- `ElevationParams` — controls the height distribution of the terrain
- `RiverParams` — governs river placement and behavior
- `WorleyParams` — configures Worley (cellular) noise characteristics
- `CompositionParams` — the high-level terrain feature configuration described above
- An optional `NoiseCache*` pointer — enables caching of intermediate noise results for performance optimization

The optional cache pointer is a notable design detail, indicating that this function can be used in both performance-critical contexts (e.g., real-time generation or large map builds) and simpler single-pass scenarios.

**Dependencies and Pipeline Position**

The header depends on three other modules:

- `map_data.h` — defines the terrain data structure being written to
- `noise_cache.h` — provides the caching mechanism for noise computations
- `noise_layers.h` — supplies the individual noise layer types consumed by the composer

This dependency structure confirms that `noise_composer.h` sits at the **integration layer** of the terrain pipeline — it does not generate raw noise itself, but instead orchestrates and combines the outputs of lower-level noise modules into a unified terrain representation. Developers extending or debugging the pipeline should treat this file as the primary assembly point where terrain features converge.

**Intended Audience**

This API is targeted at C++ developers building games or simulations that require procedural terrain generation. Familiarity with noise-based algorithms (particularly Worley/cellular noise) and general terrain synthesis concepts is assumed.
