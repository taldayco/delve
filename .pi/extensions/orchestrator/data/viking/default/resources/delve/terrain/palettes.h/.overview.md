# palettes.h

This directory contains a C++ header file implementing a color palette system designed for elevation-based terrain and map rendering. It provides data structures and utility functions for mapping normalized elevation float values to RGBA colors, supporting both discrete stepped and smooth gradient rendering modes. The system is built around a flexible `Palette` struct and includes predefined palette constants. It is suitable for C++ graphics developers, game developers, and anyone working on procedural terrain generation, map visualization, or elevation-driven rendering pipelines.

## Detailed Description

### palettes.md — Color Palette System for Elevation Rendering

This file documents the `palettes.h` C++ header, which serves as the core reference and API definition for the elevation color mapping system. It is organized around three primary components:

**Palette Data Structure**
The `Palette` struct is the foundational data type in this system. It holds a name identifier alongside an array of six RGBA color entries. This structure is designed to be flexible enough to support a range of color schemes while keeping the interface simple and consistent. The six-color capacity allows for meaningful gradient definition across the full normalized elevation range.

**Predefined Palette Constants**
The file provides at least one predefined palette constant — a `Grayscale` palette — ready for immediate use without requiring manual color definition. This serves as both a practical default and a reference example for developers who wish to define custom palettes following the same pattern.

**Color Mapping Functions**
Three inline functions handle the actual elevation-to-color conversion logic:

- `get_elevation_color`: Implements a stepped, discrete color assignment strategy. It evaluates elevation values against five fixed thresholds (ranging from 0.2 to 0.8) and assigns a flat color per band. This approach is well-suited for stylized or categorical map rendering where sharp boundaries between elevation zones are desirable.

- `get_elevation_color_smooth`: Provides linear interpolation between palette colors across four equal segments, each spanning a 0.25 range of the normalized elevation value. This produces smooth, continuous gradients ideal for realistic terrain shading or visually polished map rendering.

- `organic_color`: Extends the smooth gradient approach by introducing positional noise variation through an external `add_noise_variation` call. This function depends on utilities from `color.h`, including `lerp_color`, and is intended for use cases where natural, irregular color variation is desired — such as organic terrain textures or hand-painted map aesthetics.

**Key Design Considerations**
- Elevation values are expected as normalized floats in the `[0.0, 1.0]` range.
- All palettes support up to six colors, defining the resolution of any gradient.
- The system cleanly separates hard-stepped rendering from smooth gradient rendering, giving developers explicit control over visual style.
- External dependencies (`color.h`, `lerp_color`, `add_noise_variation`) are required for the full feature set, particularly for the organic coloring mode.

This header is intended for C++ graphics or game developers building procedural terrain generation systems, topographic map visualizers, or any elevation-driven rendering tool. Prerequisite knowledge includes familiarity with C++, basic color blending concepts, and an understanding of normalized value ranges in graphics contexts.
