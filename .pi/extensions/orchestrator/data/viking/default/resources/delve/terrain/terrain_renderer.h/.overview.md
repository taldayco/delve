# terrain_renderer.h

This directory contains the C++ header definition for the `TerrainRenderer` class, a GPU-accelerated terrain rendering system built on SDL3's GPU API. It covers multiple rendering pipelines (standard, instanced, PBR), clustered forward lighting with point light culling, mesh upload utilities, and GPU buffer management. The header is split across two reference documents detailing public API and internal state respectively. Suitable for graphics programmers and game engine developers with familiarity in GPU programming, clustered shading techniques, and real-time rendering pipelines.

## Detailed Description

### terrain_renderer_1.md terrain_renderer_1.md — Public API Reference

This document describes the public-facing interface of the `TerrainRenderer` class. It covers the full lifecycle of the renderer, beginning with `init` for GPU device setup and progressing through geometry upload methods (`upload_mesh`, `upload_gltf_column_mesh`) that transfer vertex and index data to the GPU. The `draw` method handles per-frame rendering dispatch, while `rebuild_clusters_if_needed` supports dynamic reconfiguration of the light clustering structure when the depth texture dimensions change.

Three render pass variants are documented, each differing in load behavior and depth-preserve semantics, giving callers flexibility for compositing terrain into larger rendering pipelines. Frame-level resource management is handled through `prepare_frame_resources` and `cleanup`. Accessor methods expose key GPU buffers — point lights, light grids, global indices, and cluster tile dimensions — enabling other systems to read or bind clustered lighting data.

The document also explains the depth texture lifecycle, including the distinction between desired and current dimensions and the dirty-rebuild flag that triggers cluster regeneration. Target readers are graphics or game engine developers who need to integrate `TerrainRenderer` into a scene, configure its pipelines, or extend its rendering behavior.

**Key topics:** `init`, `draw`, mesh upload, render pass variants, clustered light accessors, depth texture lifecycle, `rebuild_clusters_if_needed`, `prepare_frame_resources`, `cleanup`.

### terrain_renderer_2.md terrain_renderer_2.md — Internal State and GPU Resources

This document covers the private implementation details of the `TerrainRenderer` class, focusing on the GPU resources and pipeline objects that power its rendering. It enumerates all graphics pipeline declarations, including pipelines for terrain, lava, contour, instanced terrain, and PBR terrain rendering. On the compute side, it documents the cluster generation and light culling pipelines that implement the clustered forward shading strategy.

Geometry storage is detailed through vertex and index buffer declarations for four mesh types: basalt, lava, contour, and glTF column geometry. The document then covers the shader storage buffer objects (SSBOs) used in clustered lighting, including buffers for point lights, cluster axis-aligned bounding boxes (AABBs), light grids, global light indices, and culling counters. Two important constants are defined here: a maximum of **1024 point lights** and **65536 light indices**, establishing the hard limits of the lighting system.

Utility methods for releasing individual buffers, releasing cluster-specific buffers, and uploading light data are also described. This document is intended for graphics programmers who need to understand or modify the internal resource layout, debug GPU memory usage, or extend the pipeline set.

**Key topics:** graphics and compute pipeline declarations, vertex/index buffers, SSBOs, clustered lighting buffers, `SDL_GPUDevice`, max light constants, buffer release utilities, light upload.
